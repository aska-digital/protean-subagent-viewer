Hermes Desktop plugin · read-only fan-out viewer

See every worker. Steer none.

subagent-viewer turns the agent's async subagent fan-out into a live card view. Every spawned worker gets its own card with its goal, model, status, streaming thinking, latest tool line, and accumulated output.

This is the verified slice of the larger Chief of Staff fan-out plugin: watching spawned subagents was confirmed live, while steer and interrupt were not yet reliable. So this plugin observes and copies only.

01Install

One file in, done. The plugin root is profile-aware: copy plugin.js into the desktop plugin root of the profile you run.

mkdir -p ~/.hermes/profiles/halakukhan/desktop-plugins/subagent-viewer/
cp plugin.js ~/.hermes/profiles/halakukhan/desktop-plugins/subagent-viewer/plugin.js

Find Subagent Viewer in the ⌘K palette under the PLUGINS header and open the right-hand pane. Each plugin.js is file-watched, so edits reload live.

Use your own profile root in place of halakukhan above: the active profile root, the one your desktop actually loads. No build step, no config, no restart.

02Live worker cards

One card per spawned subagent, keyed by subagent_id. Cards stream for the orchestrator that spawned the fan-out, following the active session id.

goal + status

What it is doing

Each card shows the worker's goal and a status badge:

runningdoneinterruptederrored

model · read-only

Who is running it

The worker model is shown as resolved by delegation, read-only. Streaming thinking is collapsible and capped around 2KB, with the latest tool line under it.

accumulated output

Everything it wrote

Every subagent.text chunk is appended to the output preview, never overwritten. A show-all toggle reveals the full stream.

Active / Past toggle

Split the view between running workers and finished, interrupted, or errored ones. All workers stay in state. Only the render is filtered.

Ownership-gated viewing

The pane follows the active session id and streams cards for the orchestrator that spawned the fan-out. With no active workers, the empty state explains the flow.

03Copy output for forward

When a worker finishes, one button puts its complete final answer on your clipboard for handoff. The copy grabs the full final_response from the orchestrator's live session history first.

Fallback order when the full final answer is not there: the event summary, then the last tool results, then the accumulated buffer. The best available content is copied, never an empty clipboard.

  • Flow: post a delegate_task fan-out in the orchestrator session. Worker cards appear live as the subagents spawn.
  • Watch: goal plus status badge, streaming thinking, latest tool line, accumulated output.
  • Toggle Active/Past to review finished workers.
  • Copy a worker's full final answer with one click.

04Scope guards

The plugin's contract is restraint. It watches the fan-out and copies output. Everything else is out of scope by design.

It neverMeaning
Steers or interruptsNo control actions on workers or the orchestrator session
Spawns subagentsWorkers shown are real subagents from delegate_task. The plugin creates none
Touches the room logDoes not read or write the room log or group-chats localStorage
Phones homeNo telemetry. All state is local to the running desktop process

Requirements: Hermes backend v0.21.0 or newer. It must expose the subagent.* event stream (including summary and output_tail on subagent.complete) plus a live worker list. The pane ladders between session.info (carrying active) and delegation.status.
